## Latest source behavior and compatibility

The current wizard is Source → Transformation → Destinations → Review & Test. Step 2 contains Source Field / Target Field mappings, searchable pickers, Add Mapping and optional Advanced Custom Transformation Script. Required/default/conversion remain in collapsed Mapping options. Source optionally analyzes a synthetic sample into one reusable field tree; it does not execute delivery tests. Each destination owns its output format and HL7 profile independently. XML root configuration is explicit inside destination mapping options; existing metadata is retained without an automatic Patient wrapper.

Review & Test owns transformation tests, generated output, safe actionable errors and optional audited raw preview under Advanced test options. Parsed input is fully redacted by default; HL7 tree exposes metadata only. Explicit TCP/TLS connection probes also live there after configuration is complete. Transformation preview performs no DNS lookup or delivery; connection probes send no application data. Confirmed post-save synthetic delivery remains separate. The shared pipeline/converter are reused; V2 adds a bounded mapper/template stage inside the existing sandbox and preserves V1 canonical behavior.

Validation, simple Field/Operator/Value filters and source/destination transformer settings remain progressively disclosed. Response editors stay hidden while legacy response scripts, custom validation, arbitrary filters/transformers, routing, retries, multiple destinations, redaction and revision snapshots remain supported. Draft audit summaries remain automatic. This follow-up does not change the engine, converter or database schema; schema 1–7 remains required.

Migration `007_delivery_timing.sql` adds nullable integer `MessageDestinationLog.request_duration_ms`. Duration is captured around actual transport calls; admission/circuit/backpressure events do not become delivery attempts. Attempt counts use complete retained history for each outbound message. Legacy or mixed history without sufficient captured timing returns an unknown count rather than a fabricated value. Existing duration data remains `NULL`; no payload or business-data deletion is part of this upgrade.
