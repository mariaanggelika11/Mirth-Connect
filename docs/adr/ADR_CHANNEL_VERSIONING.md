# ADR: channel revision lifecycle

Status: implemented; production workload verification required.

Problem: replacing a running channel's source/script/destination configuration immediately makes accepted work difficult to reproduce and rollback unreliable.

Decision: retain Channels/Destinations as the compatible materialized runtime API. Store encrypted immutable ChannelRevisions with number/state/checksum/summary/actor/timestamps; migrate existing channels as their first published revision. PUT channel saves the latest draft and archives preceding drafts under the channel lock, preserving runtime state. Publish and rollback lock the channel and compare expectedActiveRevision; activation creates a new published snapshot with the actual materialized destination IDs, then archives pending drafts. Rollback reuses a prior published configuration but creates new activation history and cannot target the already active revision. Older legacy competing drafts are displayed as SUPERSEDED and cannot publish. Active published snapshots remain immutable.

Inbound reads source and destination snapshot under a shared channel lock and revalidates existence/RUNNING/revision under another shared lock held through reservation, preventing a stale snapshot from being accepted after stop/delete/archive/publish. Jobs record the accepted channel revision and encrypted destination/final payload; retry never rereads active scripts. Source API keys remain live channel credentials independent of revisions, preventing rollback from reviving an old credential. Diff omits endpoint auth/query and all script contents; script checksums are a future enhancement. Removed destinations retain their historical IDs.

Lifecycle correction (17 October 2026): ADMIN may DELETE a STOPPED channel without retained messages, including unused duplicates with revision 1. Remove its revisions and destination runtime records transactionally with connectors/channel, retaining audit. Any retained message prevents DELETE. ADMIN may instead archive a STOPPED channel with no pending/leased work: set existing status to ARCHIVED, retain all revisions/messages/audit, hide from the default list and expose with includeArchived=true. This adds no table/column or migration. Archived channels cannot start, edit or publish; duplicate into a new reviewed channel when a replacement is needed. Existing retention remains unchanged; deletion checks retained evidence, not a permanent ever-used flag after approved retention has already removed all messages. Do not manually clear evidence to enable deletion.

Compatibility note: existing routes and success envelopes remain, but clients expecting PUT to change running configuration must now explicitly review/publish. See README V2 migration instructions. This is an intentional safety behavior change, not a claim of completely unchanged semantics.

Legacy published snapshots without connector IDs reuse a same-channel matching connector deterministically and one-to-one, including retired records (retirement's enabled flag is excluded from configuration identity). Subsequent activations persist actual IDs; original encrypted historical snapshots remain unchanged. Do not downgrade to a binary that does not enforce ARCHIVED lifecycle protections without an access/operations review.

Consequences: migration account needs new table/column/index permissions; runtime account needs CRUD on new session/runtime tables. Saved drafts remain immutable. PATCH with expectedChecksum creates a successor DRAFT and archives its predecessor within the channel lock; concurrent edits/publish return 409. Only an explicit public subset is patchable, retaining private scripts/credentials server-side. Stored-revision dry-run uses the encrypted configuration and returns a masked synthetic preview without network delivery. A separate explicit destination probe opens DNS/TCP/TLS only and audits the request. Private script/endpoint draft editing still requires a broader credential-preserving contract. Compare shows sanitized before/after configuration rather than a full text patch.
